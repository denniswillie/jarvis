## Fingerprints, authority and scope

Three identities are distinct:

1. `source_bundle_sha256`: SHA256 of canonical sorted `{path,size_bytes,sha256}` entries in `source-lock.json`. It covers the qualified source/lock/font copies.
2. `recipe_sha256`: SHA256 of canonical pins + source-bundleSHA + hashes of the recipe/build/install/inventory/entrypoint files. It identifies the reviewed build instruction, **not** an installed environment.
3. `software_sha256`: generated only inside an actual build. Schema `jarvis.clip.software.v2` covers protected root/ancestor metadata, sorted installed paths/types/modes/owners/contentSHA or symlink targets under `/opt/jarvis-render`, build-measured tool versions, exact dpkg package versions/architectures, Core prerequisite command hashes/resolved paths/modes/owners/protected parents and the sealed entrypoint hash. Only the resulting inventory file itself is excluded to avoid self-reference. Job inputJSON, recordings, work directories, outputs, logs and timestamps live outside that tree and are excluded. The new schema/recipe needs a new measured fingerprint; the old image receipt cannot stand in for it.

`inventory.py --write` executes and pins version evidence at build time. Runtime `--verify` first checks root/ancestor/receipt protection and the saved receipt's own canonical SHA256, then recomputes the same exact immutable payload and Core identities using those already-measured version values. It still invokes the existing bounded `/usr/bin/dpkg-query` and compares its package list. It does **not** launch Chrome, npm, Node, FFmpeg or ffprobe for version strings on each verify. Exact UID, mode and hash guard failures name the failed operand/path. No saved receipt is accepted merely because it exists, and content/permission checks are not weakened. Actual executable readiness is a separate outcome proved by the existing bounded real render, decode and audio/frame inspection—not by version output or a recipe build.

Do not manufacture a recipe's trusted `bundle_sha256` from a package version or source hash. OS package version recording and the image pin are not a claim of cross-platform bit-identical output.
